# automatic-library

Content library for [Automatic](https://github.com/velvet-tiger/automatic). The Automatic desktop app extracts a snapshot of this repository on first run and refreshes from tagged releases in the background.

Assets in scope:

- **Skills** — under `skills/`, one directory per skill.
- **Rules** — under `rules/{pack}/{name}.md`.
- **Instructions** — under `instructions/{name}.md`.
- **Subagents** — under `subagents/{pack}/{name}.md`.
- **Hooks** — under `hooks/{name}.json`. See `hooks/README.md` for the format and the security policy.

Assets that remain in the app repository (registries, agent adapters, discover UI content) are not part of this library.

## How the app consumes this repo

1. Every Automatic release ships a snapshot tarball of a pinned library version, embedded in the binary.
2. On first run, the app extracts the snapshot to `~/.agents/library/current/`.
3. In the background, the app polls GitHub Releases for a newer library version compatible with the app's supported range.
4. When a newer version is available, the app downloads `library-vN.tar.gz` and its signature, verifies both, then atomically swaps `current/` to the new version. The previous version is kept at `previous/` for one-step rollback.
5. `manifest.json` is the source of truth for what the library contains. The app never walks the extracted tree to discover assets.
6. Library assets are read-only templates. When a user edits an asset in the app, it forks into their own store under `~/.agents/`. Upstream updates never overwrite user edits.

## Layout

```
skills/
  {skill-id}/
    SKILL.md            # required
    ...
rules/
  {pack}/{name}.md
instructions/
  {name}.md
subagents/
  {pack}/{name}.md
hooks/
  {name}.json
manifest.json           # generated by scripts/build-manifest.mjs
retired.json            # records assets removed from the library
VERSION                 # semver, drives release tags
LICENSE                 # MIT
```

## Contributing

1. Fork and branch.
2. Add or edit assets under the matching directory.
3. Run `node scripts/build-manifest.mjs`. This must succeed and the resulting `manifest.json` must be committed alongside your changes.
4. Bump `VERSION` if the change should trigger a new release. Patch bumps are appropriate for content edits, minor bumps for new assets, major bumps for removals or structural changes.
5. Open a pull request. Every hook change and every removal is reviewed by a human before merge.

## Removals

When an asset is removed, add an entry to `retired.json` in the same commit. The Automatic app reads this file on library refresh and detaches the retired asset from any project that still references it. Deleting an asset without updating `retired.json` will orphan those references.

```json
{
  "retired": [
    {
      "kind": "rule",
      "pack": "automatic",
      "id": "example",
      "retired_in": "0.3.0",
      "reason": "Superseded by rules/automatic/replacement.md"
    }
  ]
}
```

## Releases

1. Bump `VERSION`.
2. Run `node scripts/build-manifest.mjs` and commit.
3. Tag `vX.Y.Z` and push. CI (to be added) builds and signs `library-vX.Y.Z.tar.gz`, then publishes it as a GitHub Release asset.
