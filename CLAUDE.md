# CLAUDE.md — automatic-library

Contributor and agent guide for this repository.

Public overview and how end-users install Automatic: see `README.md`. How the Automatic app consumes this repository: see `docs/library.md` in the `automatic-app` repository.

## What this repository is

Content only. Skills, rules, instructions, subagents, and hooks that the Automatic desktop app extracts on install and refreshes from tagged releases. No application code lives here.

Assets that are code or code-adjacent (agent format adapters, discover-page content, curated MCP-server registry, language modules) stay in `automatic-app` and are out of scope for this repository.

## Layout

```
skills/{id}/                     # one directory per skill, SKILL.md required
rules/{pack}/{name}.md           # one rule per file, grouped by pack
instructions/{name}.md           # flat directory, filename stem is the id
subagents/{pack}/{name}.md       # one subagent per file, grouped by pack
hooks/{name}.json                # flat directory, filename stem is the id
manifest.json                    # generated by scripts/build-manifest.mjs
retired.json                     # records assets removed from the library
VERSION                          # semver, drives release tags
scripts/build-manifest.mjs       # walks the tree, rebuilds manifest.json
```

## Adding an asset

1. Add the file or directory under the matching kind's root.
2. Run `node scripts/build-manifest.mjs`. It rewrites `manifest.json` with new entries and updated sha256s.
3. Commit both the new content and the updated `manifest.json` in the same commit.
4. Bump `VERSION` if the change should ship as a release. Rule of thumb: patch for content edits, minor for new assets, major for removals or structural changes.
5. Open a pull request.

Naming conventions:

- **Skill id** = the directory name. Lowercase, hyphen-separated. Must be unique across the library.
- **Rule pack** = the parent directory under `rules/`. **Rule id** = the filename stem. The Automatic app usually surfaces rules as `{pack}-{id}` (for example `automatic-guardrails`).
- **Instruction id** = the filename stem, spaces allowed (`Agent Project Brief`).
- **Subagent pack** and **id** follow the rule convention.
- **Hook id** = the filename stem.

## Retiring an asset

Never just delete a file. The Automatic app has to know a retirement happened so it can detach the asset from any project that still references it. A silent delete orphans those references.

1. Remove the file.
2. Add an entry to `retired.json` in the same commit:

   ```json
   {
     "kind": "rule",
     "pack": "automatic",
     "id": "example",
     "retired_in": "0.3.0",
     "reason": "Superseded by rules/automatic/replacement.md"
   }
   ```

3. Rerun `node scripts/build-manifest.mjs`.
4. This is a breaking change for anyone relying on that asset. Bump the major version in `VERSION`.

## The manifest is source of truth

The Automatic app reads `manifest.json` to discover assets. It does not walk the extracted tree. That means:

- A file added to the tree without a manifest rebuild is invisible to the app.
- A hash in `manifest.json` that does not match the file on disk causes the app to reject the release.
- The generator is deterministic. If `git status` shows a dirty `manifest.json` after running the script, commit the delta.

## Hooks are executable content

A hook is a JSON file that instructs an agent to run a command on a specific event. Merging a hook into this repository means that code will run on end-users' machines. Every hook change is reviewed by a human before merge. See `hooks/README.md` for the format and the security policy the Automatic app enforces around signed manifests and hash pinning.

## Releases

1. Bump `VERSION`.
2. Run `node scripts/build-manifest.mjs` and commit the result.
3. Tag `vX.Y.Z` and push.
4. `.github/workflows/release.yml` verifies the tag matches `VERSION`, verifies `manifest.json` is up to date, builds `library-vX.Y.Z.zip`, signs it with minisign, and publishes the archive plus `.minisig` as a GitHub Release asset.

The signing keypair is generated once per project. See [KEYGEN.md](KEYGEN.md) for how to generate it, store the private key in Actions secrets, and hand the public key to the Automatic app.

Pull requests are checked by `.github/workflows/pr.yml`, which fails the build when `manifest.json` is out of date with the tree.

## What not to put here

- Secrets, API keys, credentials, or environment-specific URLs.
- User personal data or references to individual users.
- Application code, build tooling for the Automatic app, or agent format adapters.
- Documents describing how the Automatic app is built or deployed. Those belong in `automatic-app` or `automatic-meta`.
